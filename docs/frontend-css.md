# Frontend CSS Conventions

Этот документ фиксирует правила написания CSS и интеграции со фронтенд-стеком (Alpine, HTMX, Sortable) для проекта Midgard Nexus. Все новые стили, а также правки существующих, должны следовать этим правилам.

## 1. Классы и БЭМ

Мы используем гибридный подход к БЭМ (Блок-Элемент-Модификатор):

- **Block (Блок)**: Сущность, которая имеет самостоятельный смысл. Например, `.vor-chip`, `.vor-modal`, `.vor-artwork-row`. Для избежания конфликтов имен каждый модуль использует свой префикс. Для первого модуля (`vor_archives`) это префикс `vor-`. В названии блока `vor-artwork-row` префиксом является только `vor-`, а `artwork-row` - это цельное имя блока. Вложенных префиксов нет. Общие блоки уровня всего приложения (`nav-btn`, `sidebar-btn`, `module-card`) пишутся без префикса модуля, но подчиняются тем же правилам БЭМ.
- **Element (Элемент)**: Часть блока, которая не может использоваться отдельно. Пишется через два подчеркивания: `.vor-chip__tip`, `.vor-artwork-row__title`, `.nav-btn__icon`. Вложенных элементов вида `block__el1__el2` не допускается - при необходимости создается новый блок или составное имя элемента (`block__el1-el2`).
- **Modifier (Модификатор)**: Изменяет внешний вид или поведение блока/элемента. Пишется через два дефиса: `.vor-chip--off`, `.vor-artwork-row--selected`, `.sidebar-btn--add`.
- **State (Состояние)**: Семантически совпадает с модификатором, также пишется через `--`. Старые конструкции `.is-*` и `.has-*` не используются. Для состояний с предлогами/вспомогательными словами используется префикс `--with-`: `.vor-field--with-error`, `.vor-context-item--with-submenu`.

### 1.1. `data-*` атрибуты вместо классов-режимов

Если элемент может находиться в одном из нескольких **взаимоисключающих** глобальных режимов, используйте `data-*` атрибуты вместо классов:

- Режим отображения списка: `[data-view="list"]` / `[data-view="grid"]`.
- Режим редактирования: `[data-mode="normal"]` / `[data-mode="delete"]`.
- Состояние Drag-and-Drop: `[data-dragging="list"]`, `[data-dragging="grid"]`.

Это упрощает JS (`element.dataset.view = "grid"` вместо `classList.toggle`) и снижает специфичность.

## 2. CSS-переменные (Токены)

Все цвета, отступы, тени и z-index выносятся в CSS-переменные в глобальном скоупе (в настоящее время в `:root` файла `main.css`).

- **Нейминг**: kebab-case с префиксом группы: `--bg-primary`, `--text-secondary`, `--accent-vor`, `--radius-sm`, `--shadow-lg`.
- **Цвета с прозрачностью**: Используйте относительный синтаксис цвета (Relative Color Syntax), чтобы не дублировать RGB-каналы. Не используйте `rgba` с хардкодом или `color-mix` без необходимости.
  Пример: `background-color: rgb(from var(--accent-vor) r g b / 10%);`
- **Возрастные рейтинги**: Имеют свои независимые токены (`--age-ok-bg`, `--age-warning-bg`), даже если их значения совпадают с системными (`--success`, `--accent-kvasir`). Это позволяет менять их независимо.

## 3. Z-index

Все `z-index` строго регламентированы и вынесены в токены. Использование "магических чисел" запрещено.
Есть два диапазона:

- **Внутренние (1-60)**: Для элементов внутри позиционированных родителей. Не конкурируют с глобальным интерфейсом.
    - `--z-base` (1): Базовый уровень.
    - `--z-raised` (2): Чуть выше соседей (например, панель информации над панелью связей).
    - `--z-overlay-bar` (10): Липкая шапка оверлея.
    - `--z-popover` (20): Выпадающие меню, тултипы.
    - `--z-picker` (40), `--z-tooltip` (50), `--z-hover-preview` (60).
- **Глобальные (900+)**: Для fixed-элементов (навбар, сайдбары, модалки).
    - `--z-sidebar` (1000), `--z-overlay` (1020), `--z-backdrop` (1030), `--z-leave-confirm` (1050).
    - `--z-navbar` (1070), `--z-context-menu` (1100).

## 4. `!important`

Использование `!important` запрещено, кроме случаев, когда необходимо переопределить inline-стили сторонних библиотек или виджетов, которые невозможно перебить через специфичность.

Все остальные конфликты решаются за счет правильного порядка подключения файлов и специфичности.

## 5. Интеграции

### 5.1. Alpine.js

- Используйте `:class="{ 'vor-chip--off': condition }"` для динамических классов.
- Используйте `:data-attribute="value"` для режимов.
- Не используйте несемантичные или слишком общие имена классов (например, `'active'` без префикса), так как они могут пересечься с другими библиотеками.

### 5.2. Sortable.js

Классы состояний для перетаскивания (ghost, chosen, drag) должны следовать общей конвенции именования модификаторов, например `vor-artwork-item--ghost`. Они передаются в конфигурацию Sortable как `ghostClass`, `chosenClass`, `dragClass`.

### 5.3. Javascript (Vanilla)

При чтении `data-*` атрибутов помните про camelCase: `data-collection-id` читается как `element.dataset.collectionId`. Не добавляйте префикс `vor-` к `data-*` атрибутам, если этого не требует логика.

## 6. Bootstrap

В настоящее время Bootstrap используется для сеток, базовых утилит выравнивания, типографики, форм и иконок. Кастомные компоненты (кнопки, карточки, модалки, аккордеоны) реализуются через собственные классы.

Жестких ограничений на использование компонентов Bootstrap нет. В будущем возможен пересмотр в пользу Bootstrap-компонентов (например, аккордеонов или модалок), если это упростит поддержку.
